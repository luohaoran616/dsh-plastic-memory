## 五、Task 7 Step 1：隔离实例并发试跑（controller 直接执行）

现场与计划有出入：计划写「3085 隔离实例（dsh-clean-web）」，但 3085 的 web profile 装的是**已发布的 dsh-plastic-memory@0.2.0（npm 包）**，
不含本轮改动；**本 fork 装在 3086（dsh-dev-web）**（`file:` 链接、从源码加载、启动日志 `state: active`）。故两台都跑：
3086 验同版本互斥，3085 验**跨版本互斥**（对应 spec §一 的锁契约「新旧版本同开时要锁同一个文件、用同一种方式才互斥」）。

配置手法：`--patch` 叠加层覆盖 `plastic-memory` 的 `memoryRoot` 指向临时测试根（config 是整体替换、不深合并，故 writeMode/template 一并写上），
**未污染 profile 常驻配置**。memoryRoot 非 volatile，故每次试跑都起独立进程生效。

结果（两台都通过）：

| 项 | 3086（本 fork） | 3085（已发布 0.2.0） |
|---|---|---|
| DSH 侧 | headless 会话 `memory_save` 写入成功，exit 0 | 同上，exit 0 |
| MCP 侧 | 20 条同标题写全成功，0 错误 | 20 条同标题写全成功，0 错误 |
| 记忆文件 | 42 个 | 21 个 |
| 互异 id | 42 / 42 | 21 / 21 |
| 正文互异（无覆盖） | 是 | 是 |
| 锁降级告警 | 无 | 无 |

同名标题在同目录并存为 `并发记录-N.md` 与 `并发记录-N-<id片段>.md`——排他占名按设计追加 id 片段，不互相覆盖。
**两台实例的真实记忆根在试跑期间零改动**（试跑后 `find -newermt` 计数均为 0）。临时根与临时脚本已清理。

**对两台实例留下的持久改动（需人工知晓）**：为让 headless 会话能调 `memory_save`，往两台的 `headless` profile 各装了一个插件——
3086 装的是本 fork（`link:` 到仓库），3085 装的是已发布的 `dsh-plastic-memory@0.2.0`（npm 包，用于跨版本互斥验证）。
两台的 `memoryRoot` **未被改动**（试跑用 `--patch` 叠加层指向临时根，未写进 profile 常驻配置），
所以这两处插件安装只影响「headless profile 现在带着塑料记忆插件」，记忆根仍按缺省解析。
若不想保留，`dsh plugin --profile headless remove dsh-plastic-memory` 可回退。
