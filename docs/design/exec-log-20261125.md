### 裁决清单（R28 至 R36）

**R28** 问题是 serve 模式的模型线路由谁装配。结论是 `packages/mcp/src/bin.ts` 的 serve 分支除动态导入 `createGuiPlane` 外，还要动态导入根包产物 `lib/standalone/llm.js` 里的 `createAnthropicLlm`。理由是 `parseGuiEnv` 只解析出模型配置，导入适配器才有模型可用，`/memory model-info` 才会回可用而不是 llm-unavailable，Task 9 的第六条接口证据才过得去。代价是这一步若判断错了，serve 模式会没有模型，症状明显，回补容易。

**R29** 问题是开工前的准备要不要重做。结论是 worktree 与 pnpm install 都不重做，沿用已建好的工作树与已装好的依赖。理由是用户指令明确要求不重做，基线命令在开工前已经跑过并记在案。代价无。

**R30** 问题是根包产物要出类型声明，而 `src/index.ts` 里 Config 的推断类型含 cosmokit 的 Dict，编译报 TS2742。结论是选第二条修法，把 cosmokit 放进 devDependencies 并补一份可选的类型声明垫片，`src/index.ts` 一行不改。理由是硬约束要求不改 `src/index.ts`，且 `lib/index.d.ts` 的类型泄漏眼下没有在库消费者，MCP 只吃平面的闭包，DSH 从源码直载，esbuild 不查类型。代价是将来若有消费者引用 `lib/index.d.ts`，需要 cosmokit 可解析，发布清单还应补一条 cosmokit 的 peerDependency 或 Config 注解，另外任务书漏了提交 lockfile，这一步由实现者补上。

**R31** 问题是独立服务的 `openLegacyKv` 能不能按计划省略。结论是不省略，改成一次永远不写结清标记的探针。理由是省略会写下 `source:'none'` 的永久结清标记，共享记忆根下会把宿主真正的旧数据导入一并跳过。代价是每次侧表操作多一次标记文件检查和一次根锁的短持有，直到 0.3.0 删除导入屏障为止，这一步若判断错了也只是多花开销，不会错杀数据。

**R32**（Task 3 复审时移交）问题是探针让独立平面的 `isLegacyImportSettled` 恒为假，彻底删除因此用不了。结论是接受这一状态，记为后续项，本轮不改。理由是它由 R31 的探针选择带来，进程内的备忘值不随宿主结清更新，重启也不变，要等 0.3.0 删除导入屏障才自然消失。代价是独立服务里的 `/memory hard-delete` 会回「旧数据迁移还没收尾」。

**R33** 问题是来源校验按字面比对时，用 localhost 打开页面的写请求全被拒。结论是来源比对接受同端口的 localhost 与 127.0.0.1 互换，端口必须一致，外来的来源、`Origin: null` 与 `text/plain` 的简单请求照拒。理由是字面规则会让本机正常打开页面却写不动。代价是这条若判断错了，也只是把写权限给了本机回环同端口的来源，没有跨站暴露。

**R34** 问题是 serve 进程里 core 与 GUI 平面各建一把写锁。结论是先在 Task 4 记下并转 Task 7 处置，最终按加法式锁注入修，给 `createMemoryCore` 与 `GuiPlaneOptions` 加 `lock` 选项，bin 的 serve 分支建一把锁两处共用。理由是核实过 `createMemoryCore` 的调用方只有 MCP 的 stdio、serve 与导入三处，DSH 插件不走这个工厂，热重载时各建各锁的互斥语义没有被触碰，工厂对插件的排除条款仍然守得住。代价是最坏情况是并发行为退回修复前的等价状态，不引入新的风险，注入后两个 FileTable 不再互斥这件事记在后续项里。

**R35** 问题是提前看到的两条风险要不要在实现阶段就改。结论是两条都不改代码，按计划既有决定接受，记为后续项。理由是网关不发 Authorization 与「独立页面不带 --token 运行」这条既定决定一致，vite 的开发代理不在计划内，部署路径是 dist 同源托管，部署形态下不受影响。代价是开发态下用 vite 代理发起的 POST 会被来源校验拒绝。

§八 清单里的三条遗留随这一轮关闭。第一条是「REST 在无 token 模式下不做 Origin/Host 校验，跨源简单 POST 可触发提升或恢复」，独立的记录面已删除，新的两个写接口只收 JSON 并校验来源。第二条是「WebUI 提升无快照，不进 DSH GUI 的撤销历史」，页面改为经 `/memory` 命令走真正的执行器，提升的快照与撤销由执行器保证。第三条是「WebUI health 与插件 health 是两套度量，阈值一致、数字不同」，页面的健康分与插件的健康分出自同一套度量，数字不再是两套。

### 后续项

- `src/index.ts` 与 `src/standalone/plane.ts` 的装配重复约四十行。这是设计说明里就记下的后续项，等两边装配再动一次时一起收。
- `--token` 与页面不配套。页面没有输入口令的地方，网关也不发送 Authorization 头，独立页面因此只能不带 `--token` 运行，服务只绑定本机回环地址是唯一的防线。
- 自动体检在独立服务缺省关闭，只有 `PLASTIC_AUTO_CHECKUP=1` 才启动调度器。这是设计说明里的取舍，不是缺陷。
- 开发态用 vite 代理（localhost:5173）发起的 POST 会被来源校验拒绝。部署路径是 dist 同源托管，开发态这条限制本轮接受。
- `packages/webui` 的 `diff` 与 `zod` 两条依赖已无源码引用，清理要连 lockfile 一起动。
- serve 进程内 core 与 GUI 平面各有一个 FileTable，不再互斥。rename 是原子的，文件不会写坏，操作级锁本来就不覆盖跨子系统的读改写交错，丢更新的窗口先前同样存在，跨进程互斥与插件同形。若要收口，可让 serve 共用一个 FileTable。
- bin.ts 的锁接线没有用例钉住，删掉 lock 注入仍然全绿。根包产物版本错配时 lock 选项被静默忽略并退回双锁，本地 monorepo 部署不受影响。
- hard-delete 在独立服务暂不可用。R31 的探针让 isLegacyImportSettled 恒为假，0.3.0 删除导入屏障后自然消失，进程内的备忘值重启也不更新。
- 旧设计文档 `docs/design/2026-11-25-mcp-core-webui-plan.md` 里仍描述已删除的记录 REST 面。本轮按任务书只改 README 与本执行日志，没有动它。
- 独立页面没有按来源筛选的入口。上一轮 §八 记的「WebUI 缺来源过滤与跨项目枚举」没有整条关闭。跨项目枚举由原版记忆页的「全部」作用域承担，它列出各项目与全局。按来源筛选仍然没有做，是仍开着的能力缺口。
- 发布前须给 `publishConfig.exports` 补一条 `./lib/standalone/*`。设计说明 D1 明言发布时 `publishConfig.exports` 整体覆盖导出表，所以发布物里没有这条子路径。`@plastic/mcp` 在 serve 模式动态导入 `dsh-plastic-memory/lib/standalone/plane.js` 与 `llm.js`，发布出去的包会报 ERR_PACKAGE_PATH_NOT_EXPORTED，而包内那句提示会让人以为是忘了构建。本仓本地部署不受影响，因为 `@plastic/mcp` 依赖的是 workspace 链接的本仓源码包。
