## 二、逐任务裁决与偏差

- **Task 1（设置文档）**：`unset` 语义定为「只删显式改动」——unset 作用在 `set` 树上再叠出厂值，
  而不是从叠加结果里删键（否则 unset `template` 会把必填字段删没）。core 只管文件（`DocFileTable`：
  原子写、签名缓存、锁内读改写、坏文件不覆盖），语义全在插件层 `src/governance/memory-settings.ts`。
- **Task 2（上下文平面）**：`resolveProject` 严格解析（realpath、必须存在的绝对路径），但 save 的
  落盘点不用它——落盘保持旧语义（PLASTIC_PROJECT 原文、目录可不存在），只有显式传路径时才先试
  realpath、失败退回原文解析。
- **Task 3（GUI 平面与 REST）**：`/api/gui/settings` 的 GET 对 ready 与 unavailable 都回 200（body 带
  status）；POST 冲突 409 带当前版本号（`x-plastic-settings-revision`），坏文件 409
  （`settings/unavailable`），内容不合法 400。计划里的「`/mcp` 的 tools/list 是六个」随 Task 5 落地。
- **Task 4（设置页）**：置灰说明走 webui 自己的词典键（`webui.inert.manage`），不进根包 client 词典
  （import-direction 的「每条文案键都有引用」守卫只扫 client/）。`ConfigForm` 被拒后先重读再回 false，
  与宿主「拒绝时已重读」的契约一致。
- **Task 5（工具面）**：`PLASTIC_PROJECT=global` 与显式 `project: "global"` 同一条守卫（旧实现如此，
  实现时曾丢掉，测试拦回）。memory_save 新建必填 `type`（场景枚举），更新缺省沿用目标；
  全局候选标记用管线的 `globalCandidate`（替代旧工具私加的 `needs-promote-review`，与插件治理同码）。
  工具面全部走结构子集类型（`MemoryContextPort` / `ToolSaveInput` / `ToolSaveOutcome`），
  mcp 包不 import 插件源码。stdio 模式从此依赖根包构建产物（计划风险 1 的提示已实现：缺产物时
  启动即报「先在仓库根目录跑 pnpm build」）。
- **Task 6（hook 与插件）**：hook 模块不 import 上下文平面（只走 HTTP），stdio 模式不因 hook 背根包
  构建产物依赖；bin 增 `hook-snapshot` 子命令。插件产物指向仓库内已构建的 `packages/mcp/lib/bin.js`
  （非自包含）。`${CLAUDE_PROJECT_DIR}` 在 env 里的展开属待实测项（Task 8）。
